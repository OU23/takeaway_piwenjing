# 富店铺卡片组件功能规格说明（RichShopCard）

> 组件文件：`frontend/src/components/RichShopCard.vue`
> 配套使用方：`frontend/src/views/SearchView.vue`（搜索结果页）
> 版本：v1.0 · 修订日期：2026-10-27
> 设计参考：京东外卖搜索结果页（富店铺卡：外卖标签 + 评分/月售/时长/距离同排 + 券卡 + 爆款商品行）

---

## 1. 组件定位

| 项 | 说明 |
|---|---|
| 用途 | 在列表场景中展示单家门店的**概览信息 + 营销券卡 + 爆款商品**，驱动「搜索即下单」的短链路转化 |
| 设计目标 | 视觉对齐京东外卖富卡片；数据全部外部传入，组件自身**无副作用、可复用** |
| 现有使用场景 | 搜索结果页（`SearchView`）店铺列表 |
| 不适用场景 | 首页/附近的紧凑型卡片（仍使用 `ShopCard.vue`，见 §7 待确认） |

---

## 2. 功能模块

### 2.1 店铺信息头（`.rc__head`）

| 子元素 | 字段/条件 | 视觉规则 |
|---|---|---|
| 外卖红标 | 固定文案「外卖」 | 红→深红渐变小角标（`rc__wm`，`linear-gradient(135deg,#FF5B4A,#E02E24)`） |
| 店名 | `shop.name` | 主标题 15px / 700，单行省略 |
| 准时速+ 角标 | 仅当 `shop.etaMinutes` 存在时显示 | 红色细边框小标签（`rc__ontime`） |
| 同行指标 | `shop.rating`、`shop.monthSales`、`shop.etaMinutes`、`shop.distanceKm` | 同一行：`<评分>分 月售<X> 约<X>分钟 <X>km`；缺值项自动隐藏，不占位 |
| 起送 / 配送费 | `shop.minPrice`、`shop.deliveryFee` | `起送¥X`；`deliveryFee===0` 显示「免运费」，否则「配送¥X」 |
| 首条满减 | `shop.promotions[0]` | 右侧红字突出（`rc__promo`，`text-align:right`，缺省不渲染） |
| 标签行 | 取 `自提更省`(当 `pickupEnabled`) + 真实 `tags`/`promotions`，**取前 3** | 「自提更省」橙色特殊样式（`rc__tag--pick`）；其余红底浅红标签 |

### 2.2 左侧券卡（`.rc__coupon`）

| 项 | 说明 |
|---|---|
| 视觉内容 | 固定营销位：「超级补贴 / ¥12 / + 超级月卡 / 9.8折 / 去开卡」 |
| 配色 | 浅橙渐变底 + 红色标题/大数字 + 橙红渐变按钮（与商品加购按钮同色系） |
| 交互 | 点击 `@click.stop="$emit('coupon')"`，由父级处理（当前 `SearchView` 提示「活动页规划中」） |
| 渲染条件 | 整段「券卡 + 商品行」仅在 `dishes.length > 0` 时渲染 |

### 2.3 爆款商品横滑行（`.rc__dishes` → `.rc__scroll`）

| 子元素 | 字段/条件 | 视觉与交互 |
|---|---|---|
| 商品图 | `d.image`（`PhImage` 占位首 2 字） | 84×84 圆角图，溢出隐藏 |
| 爆品一口价 角标 | 固定文案，覆盖所有商品卡片 | 左上红橙渐变小角标（`rc__dish-corner`） |
| 减价角签 `减X.X` | **仅当 `d.originPrice > d.price`**（`hasCut()`） | 左下红角签（`rc__dish-cut`），金额为 `(originPrice - price)` 折算元 |
| 商品名称 | `d.name` | 12px 单行省略 |
| 价格 | `d.price` | 红色 14px/700（`rc__dish-p`） |
| 月售 | `d.monthSales`（缺省 0） | 灰色 10px，弹性占位省略 |
| 加购按钮 | `d.soldOut` 控制 | 红色圆形「＋」（`rc__dish-add`）；`soldOut` 时 `disabled` 置灰；点击 `stop` 冒泡并 `@emit('add', d)` |
| 横滑 | — | 父容器 `overflow-x:auto`，卡片 `flex-shrink:0` 宽 84px |

## 3. Props 与 Emits

### Props

| 名称 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `shop` | `Object` | 是 | — | 门店概要，结构对齐 `ShopVO`：`name / headerImg / logo / rating / monthSales / etaMinutes / distanceKm / minPrice / deliveryFee / pickupEnabled / tags[] / promotions[]` |
| `dishes` | `Array` | 否 | `[]` | 店内爆款商品列表，元素对齐 `DishVO`：`id / name / image / price / originPrice / monthSales / soldOut / hasSpec` 等 |

### Emits

| 事件 | 载荷 | 触发时机 | 父级预期处理 |
|---|---|---|---|
| `click` | — | 点击店铺信息头或商品卡片 | 跳转店铺详情页 `goShop(id)` |
| `add` | `DishVO d` | 点击商品「＋」(非售罄) | 无规格直接 `addToCart`；有规格跳店铺页选规格 |
| `coupon` | — | 点击左侧券卡 | 提示活动页（当前 toast「活动页规划中」） |

## 4. 数据来源与排序规则

| 项 | 规则 |
|---|---|
| 门店数据 | 由父级从 `GET /api/v1/shops`（列表/搜索）取得，整体传入 `:shop` |
| 商品数据 | 由父级对结果中每家店调用 `GET /api/v1/shops/{shopId}`（店铺详情含 `dishes`）获取 |
| 排序规则 | 父级在传入前对 `dishes` 做：**按月销量 `monthSales` 降序，取前 6 条**；组件本身不排序、不截断 |
| 售罄过滤 | 父级传入前过滤 `soldOut`，组件仅对残余 `soldOut` 作置灰兜底 |
| 价格/折扣 | 组件内 `hasCut()` 校验 `originPrice > price` 才渲染「减价角签」，杜绝凭空造折扣 |
| 并发策略 | 搜索页采用 `Promise.all` 批量取详情，单店失败 `catch` 不阻塞整页，缺失门店仅不展示商品行 |

## 5. 复用性与视觉一致性要求

| 维度 | 要求 |
|---|---|
| 无副作用 | 组件仅渲染与派发事件，不发请求、不修改传入数据，可安全在多页面复用 |
| 全局变量 | 沿用项目全局 CSS 变量：`--bg-card`（卡片底）、`--sh-light`（阴影）、`--t-1/--t-2/--t-3`（文字层级）、`--r-card/--r-btn`（圆角） |
| 同色系 | 主色红 `#E02E24`、橙红渐变 `#FF7A1A→#E02E24`、券卡/加购按钮共用；与 `ShopCard` 评价星色 `#FF9500` 协调 |
| 同圆角 | 卡片 12px、图片/券卡 8px、标签 3px，与 `ShopCard` 一致 |
| 占位图 | 复用 `PhImage` 组件（首 2 字占位），与全站图片缺省态统一 |
| 触摸反馈 | 沿用 `:active` 透明度/缩放反馈，符合全站可点区域规范 |

## 7. 待确认事项（TBD）

1. **扩展范围**：是否将富卡片 `RichShopCard` 替换首页「附近好店」与「附近」页现有的紧凑型 `ShopCard`？
   - 影响：首页/附近卡片变高，信息密度上升；需评估列表滚动性能与「只看店不进店」场景的阅读效率。
   - 建议：可做成开关（按页传入 `rich` prop 或在 `ShopCard` 内增加 `variant`）。

2. **券卡文案与配色可调范围**：
   - 当前「¥12 / 9.8折」为**静态营销视觉位**，未绑定后端活动数据。
   - 待确认：文案与折扣是否改为由后端活动接口下发（动态），还是保持前端可视化占位？
   - 配色是否纳入主题变量（如新增 `--brand-coupon`）以便统一换肤，还是保持组件内联渐变？

3. **商品数量阈值**：爆款行当前取前 6，是否需按屏幕宽度自适应（如小屏取 4）或暴露 `:maxDishes` prop 由父级控制？

4. **券卡与加购的事件语义**：`coupon` 目前仅 toast；是否需后续接「月卡开通 / 活动详情」真实路由？
