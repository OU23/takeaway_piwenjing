# 星光影创 · 视频生成服务方案

> 版本 v1.0 ｜ 落地载体：数创星光外卖（`merchant-web` 商家端 / `admin-web` 运营端 / `backend` Spring Boot 3 / MinIO）
> 主场景：**本地生活商家的营销短视频批量生成**（菜品展示、门店探店、优惠活动）
> 说明：架构与通用短视频创作一致，换模板与素材源即可复用于广告素材、教学视频。

## 一、需求定义

### 1.1 目标场景（按优先级）

| 优先级 | 场景 | 典型输入 | 输出规格 | 时长 | 使用方 |
|---|---|---|---|---|---|
| P0 | 菜品/套餐展示 | 3-5 张菜品图 + 卖点文案 | 9:16 1080×1920 | 15-30s | 商家 |
| P0 | 门店探店/环境介绍 | 门店图/视频 + 地址卖点 | 9:16 1080×1920 | 20-40s | 商家 |
| P1 | 平台活动/优惠券素材 | 活动规则文本 + 品牌模板 | 1:1 / 16:9 / 9:16 | 10-15s | 平台运营 |

| P2 | 图生视频 / 数字人口播 | 单图 + 口播稿 | 9:16 | 15-60s | 扩展场景 |

| 角色 | 核心诉求 | 权限范围 |
|---|---|---|

| 系统管理员 | 模型/音色/模板配置、配额与监控 | 全量 |

### 1.3 关键功能需求

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-01 | 文本/表单输入，LLM 生成分镜脚本（可编辑） | P0 | 输出结构化 JSON，字段完整率 100% |
| FR-02 | 素材选择：商家相册选图、平台素材库、文生图兜底 | P0 | 每个分镜必有可用素材 |

| FR-05 | 字幕：自动分行、关键词高亮、安全区避让 | P0 | 无溢出、错字率 <1% |
| FR-06 | 渲染导出：720p/1080p、三种画幅、封面帧 | P0 | ffprobe 校验通过 |
| FR-07 | 实时进度、失败重试、单镜头重生成 | P0 | 进度 5s 内可见 |
| FR-08 | 草稿自动保存、版本历史与回滚 | P1 | 刷新不丢稿 |

| FR-11 | 图生视频、数字人口播 | P2 | 插件式接入 |

### 1.4 非功能需求

| 指标 | 目标值 |
|---|---|
| 成片耗时 | 30s/1080p：P50 ≤ 90s，P95 ≤ 180s |
| 快速预览 | 540p 低码率预览 P95 ≤ 45s |
| 生成成功率 | ≥ 99%（含自动重试；单阶段可恢复） |
| 并发能力 | 单节点 8 路 1080p 渲染；集群 ≥ 50 路 |
| 峰值排队 | 队列等待 P95 ≤ 30s（付费优先） |
| 音画同步 | ≤ 50ms |
| 可用性 | 99.5%（渲染服务），任务不丢（持久化队列） |
| 成本 | ≤ ¥0.6/条（30s 1080p，不含人工与素材拍摄） |

### 1.5 范围边界（本期不做）

- 不做直播推流、不做影视级调色/特效、不做长视频自动分章（P2）
- 不做自动拍摄；素材来源限定为商家上传 / 平台库 / 生成图
- 不提供专业时间线编辑器；只提供「分镜级编辑 + 整片重生成」

### 1.6 成功指标

- 商家 7 日内二次使用率 ≥ 40%
- 成片直接发布率（未人工重做）≥ 60%
- 平均制作耗时从 60 分钟（人工）降至 ≤ 5 分钟（含编辑）
- 单条素材成本较外包下降 ≥ 80%

## 二、技术架构

### 2.1 设计原则

1. **编排与执行分离**：Java 主服务只做业务、权限、状态机；重计算交给独立 Worker，避免拖垮主站。
2. **阶段化流水线**：脚本 → 分镜 → 素材 → 音频 → 渲染 → 质检，每阶段可单独重试/替换实现。
3. **一切产物对象化**：中间产物（配音、分镜片段、封面）全部落 MinIO，DB 只存元数据与 URL，支持断点续跑。
4. **接口适配器化**：LLM / TTS / 图像生成 / 渲染器均为可替换 Provider，便于换供应商与降本。
5. **幂等**：任务提交与分段渲染以内容 hash 为幂等键，重试不产生重复扣费与重复文件。

### 2.3 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | Vue3 + Vite（复用现有工程与设计令牌） | 与 merchant-web / admin-web 同栈，零学习成本 |
| 编排服务 | Spring Boot 3 + MyBatis-Plus | 沿用现有后端，直接复用鉴权、Result 包装、MinIO、异常体系 |
| 队列（MVP） | MySQL 任务表 + 定时抢占（`SELECT ... FOR UPDATE SKIP LOCKED`） | 不新增中间件，单机 50 任务/分钟足够 |
| 队列（扩展） | Redis Stream / RabbitMQ | 水平扩容、优先级与死信 |
| Worker | Python 3.11（AI 生态）+ FFmpeg 6 | 图像/TTS SDK 丰富，FFmpeg 调用简单 |
| 渲染 | FFmpeg（libx264 + NVENC 可选） | 稳定、零授权成本、可脚本化 |
| 存储 | MinIO | 项目已接入，S3 兼容可无缝迁云 |
| 数据库 | MySQL 8 | 现有库，新增 6 张表 |
| 可观测 | 结构化日志 + 阶段耗时埋点 + Prometheus 指标（P1） | 定位慢在哪个阶段 |

### 2.4 流水线各阶段职责

| 阶段 | 输入 | 处理 | 输出 | 失败策略 |
|---|---|---|---|---|
| S1 脚本解析 | 卖点文本/表单 + 模板 | LLM 生成结构化脚本；规则校验 + 敏感词过滤 | `script` + `shots[]` | 重试 2 次（带错误回喂），仍失败转人工编辑 |
| S2 素材准备 | shots + 商家素材库 | 素材打分匹配；不足则文生图；统一裁切/超分 | 每镜 1 个主素材 + 备选 | 单镜降级为模板图形背景 |
| S3 音频合成 | 分镜文案 + 音色 | TTS 分段合成 → ffprobe 测时长 → 时长回写 → BGM 选曲 + 闪避 | `vo.mp3`、`bgm.m4a`、时间线 | TTS 重试 1 次，降级为默认音色 |
| S4 渲染合成 | 分镜素材 + 音频 + 字幕 | 逐镜渲染（统一编码参数）→ concat → 混音 → 烧字幕 → faststart | `output.mp4` | 从失败分镜续跑，已成功片段复用 |
| S5 后处理/质检 | 成片 | ffprobe 校验、黑帧/静音检测、音量归一、封面抽帧 | 成片 + 封面 + 质检报告 | 质检不通过自动重跑 1 次，再失败转人工 |

### 2.6 数据模型（新增 6 张表）

```sql
-- 项目（草稿/版本容器）
CREATE TABLE video_project (
  id            BIGINT PRIMARY KEY,
  merchant_id   BIGINT NOT NULL,
  shop_id       BIGINT NOT NULL,
  title         VARCHAR(64)  NOT NULL,
  scene         VARCHAR(24)  NOT NULL DEFAULT 'DISH' COMMENT 'DISH/STORE/ACTIVITY',
  aspect_ratio  VARCHAR(8)   NOT NULL DEFAULT '9:16',
  resolution    VARCHAR(8)   NOT NULL DEFAULT '1080P',
  target_sec    INT          NOT NULL DEFAULT 20,
  status        VARCHAR(16)  NOT NULL DEFAULT 'DRAFT' COMMENT 'DRAFT/SCRIPTING/READY/RENDERING/DONE/FAILED',
  version       INT          NOT NULL DEFAULT 1,
  deleted       TINYINT      NOT NULL DEFAULT 0,
  created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  KEY idx_shop (shop_id, status)
) COMMENT='视频项目';

-- 脚本（一个项目多版本，保留 history）
CREATE TABLE video_script (
  id          BIGINT PRIMARY KEY,
  project_id  BIGINT NOT NULL,
  version     INT    NOT NULL,
  hook        VARCHAR(120) COMMENT '开场钩子',
  theme       VARCHAR(255),
  cta         VARCHAR(120) COMMENT '行动引导',
  voice_code  VARCHAR(32)  NOT NULL DEFAULT 'female_warm',
  bgm_code    VARCHAR(32),
  raw_json    JSON COMMENT 'LLM 原始输出，便于回溯',
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_project_ver (project_id, version)
) COMMENT='脚本版本';

-- 分镜
CREATE TABLE video_shot (
  id            BIGINT PRIMARY KEY,
  script_id     BIGINT NOT NULL,
  seq           INT    NOT NULL,
  duration_ms   INT    NOT NULL,
  narration     VARCHAR(300) COMMENT '口播文案',
  caption       VARCHAR(120) COMMENT '字幕（可空，默认取 narration）',
  visual_prompt VARCHAR(500) COMMENT '画面描述（文生图用）',
  asset_id      BIGINT COMMENT '选定的主素材',
  transition    VARCHAR(16) NOT NULL DEFAULT 'FADE',
  motion        VARCHAR(16) NOT NULL DEFAULT 'ZOOM_IN' COMMENT 'NONE/ZOOM_IN/PAN_L',
  UNIQUE KEY uk_script_seq (script_id, seq)
) COMMENT='分镜';

-- 素材（商家上传 / 平台库 / 生成）
CREATE TABLE video_asset (
  id          BIGINT PRIMARY KEY,
  shop_id     BIGINT,
  source      VARCHAR(16) NOT NULL COMMENT 'UPLOAD/LIBRARY/GENERATED',
  type        VARCHAR(8)  NOT NULL COMMENT 'IMAGE/VIDEO',
  object_key  VARCHAR(255) NOT NULL,
  width       INT, height INT, duration_ms INT,
  tags        VARCHAR(255),
  hash        CHAR(64) COMMENT '内容 hash，用于去重与幂等',
  status      VARCHAR(16) NOT NULL DEFAULT 'READY' COMMENT 'READY/REVIEWING/REJECTED',
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_shop (shop_id, status), KEY idx_hash (hash)
) COMMENT='素材';

-- 渲染任务
CREATE TABLE render_job (
  id            BIGINT PRIMARY KEY,
  project_id    BIGINT NOT NULL,
  script_id     BIGINT NOT NULL,
  status        VARCHAR(16) NOT NULL DEFAULT 'QUEUED'
                COMMENT 'QUEUED/RUNNING/SUCCESS/FAILED/CANCELED',
  stage         VARCHAR(16) COMMENT 'SCRIPT/ASSET/AUDIO/RENDER/QC',
  progress      TINYINT NOT NULL DEFAULT 0,
  priority      TINYINT NOT NULL DEFAULT 5,
  attempt       TINYINT NOT NULL DEFAULT 0,
  idem_key      VARCHAR(64) NOT NULL,
  output_id     BIGINT,
  error_code    VARCHAR(32),
  error_msg     VARCHAR(500),
  started_at    DATETIME, finished_at DATETIME,
  created_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_idem (idem_key),
  KEY idx_status (status, priority, created_at)
) COMMENT='渲染任务';

-- 阶段明细（断点续跑依据）
CREATE TABLE render_job_step (
  id          BIGINT PRIMARY KEY,
  job_id      BIGINT NOT NULL,
  stage       VARCHAR(16) NOT NULL,
  status      VARCHAR(16) NOT NULL DEFAULT 'PENDING',
  attempt     TINYINT NOT NULL DEFAULT 0,
  cost_ms     INT,
  detail      JSON,
  KEY idx_job (job_id, stage)
) COMMENT='任务阶段';

-- 成片
CREATE TABLE video_output (
  id          BIGINT PRIMARY KEY,
  project_id  BIGINT NOT NULL,
  job_id      BIGINT NOT NULL,
  object_key  VARCHAR(255) NOT NULL,
  cover_key   VARCHAR(255),
  duration_ms INT, width INT, height INT,
  size_bytes  BIGINT, bitrate INT,
  qc_report   JSON COMMENT 'ffprobe/黑帧/响度检测结果',
  status      VARCHAR(16) NOT NULL DEFAULT 'READY' COMMENT 'READY/APPROVED/REJECTED/OFFLINE',
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_project (project_id)
) COMMENT='成片';
```

### 2.8 状态机与错误码

```
DRAFT ──script──► SCRIPTING ──ok──► READY ──render──► RENDERING ──ok──► DONE
  ▲                   │失败              ▲                  │失败
  └────人工编辑────────┴──────────────────┴──── FAILED ◄────┘
CANCELED（仅 QUEUED/RUNNING 可取消）
```

| 错误码 | 含义 | 用户可见文案 | 处理 |
|---|---|---|---|
| 30001 | 脚本生成失败 | 文案生成失败，请重试或手动编辑 | 重试 2 次 |
| 30002 | 素材不足 | 可用素材不足，请补充图片 | 提示上传 |
| 30003 | 配音失败 | 配音合成失败，请更换音色重试 | 降级默认音色 |
| 30004 | 渲染失败 | 视频渲染失败，已自动重试 | 断点续跑 |
| 30005 | 质检不通过 | 成片校验未通过，正在重新生成 | 自动重跑 1 次 |
| 30006 | 超出配额 | 今日生成次数已用完 | 引导升级/明日再试 |

## 三、功能模块

### 3.1 脚本/文本输入与解析

**输入形态（三选一，降低门槛）**

1. 一句话生成：`新店开业，招牌牛肉面 9.9 元，免费加面，地址在万达 3 楼`
2. 结构化表单：菜品名、卖点（≤3 条）、价格、地址、活动时间、目标人群
3. 素材驱动：选 3-5 张图 → 视觉模型反推标签 → LLM 补全文案

**LLM 输出契约（强约束 JSON，禁止自由文本）**

```json
{
  "hook": "9块9吃招牌牛肉面，就在万达三楼",
  "theme": "开业福利",
  "cta": "点击下单，到店自取免排队",
  "voiceCode": "female_warm",
  "bgmCode": "upbeat_light",
  "shots": [
    { "seq": 1, "durationMs": 3200, "narration": "新店开业，招牌牛肉面只要九块九",
      "caption": "招牌牛肉面 ¥9.9", "visualPrompt": "热气腾腾的牛肉面特写，暖色灯光，浅景深",
      "assetTag": "牛肉面", "transition": "FADE", "motion": "ZOOM_IN" },
    { "seq": 2, "durationMs": 3600, "narration": "现熬牛骨汤，免费加面吃到饱",
      "caption": "免费加面", "visualPrompt": "后厨熬汤场景，蒸汽，暖色调",
      "assetTag": "门店环境", "transition": "SLIDE_L", "motion": "PAN_L" }
  ]
}
```

**解析与校验（不信任模型输出）**

| 检查项 | 规则 | 不通过处理 |
|---|---|---|
| JSON 合法性 | 严格 parse | 重试（附错误信息） |
| 必填字段 | hook/cta/shots 非空 | 重试 |
| 分镜数 | 3-8 镜 | 裁剪或要求补足 |
| 单镜时长 | 1.5-6s | 截断到区间 |
| 总时长 | 目标 ±20% | 压缩文案或加镜 |
| 文案长度 | 口播 ≤ 4.5 字/秒 × 时长 | 自动精简（LLM 二次调用） |
| 合规 | 敏感词/绝对化用语/医疗宣称 | 命中即替换并标记 |

**降级策略**：LLM 连续 2 次失败 → 直接使用「场景模板 + 表单字段填空」生成脚本，保证一定能出片。

### 3.2 视觉素材的选择与生成

**素材优先级**（逐镜执行，取第一个可用）

| 顺序 | 来源 | 匹配方式 | 说明 |
|---|---|---|---|
| 1 | 本店已上传素材 | 标签 + 向量相似度（图片 CLIP，P1） | 真实性最高，优先 |
| 2 | 平台素材库（同品类） | 类目 + 标签 | 运营维护，版权可控 |
| 3 | 文生图（SDXL/ComfyUI） | `visualPrompt` + 品牌色 LoRA | 兜底，需审核 |
| 4 | 模板图形（纯色/纹理 + 文字） | — | 最终兜底，绝不空镜 |

**画面处理规则**

- 统一画幅：`scale + crop` 到目标分辨率，人脸/主体检测后按重心裁切（P1）。
- 静态图动态化：`zoompan` 缓慢推拉（1.0→1.08），避免「PPT 感」；单镜运动方向不重复。
- 转场规则：同类型转场不得连续出现 3 次；快节奏（<2.5s/镜）用硬切，情感镜头用 0.3s 淡入淡出。
- 字幕安全区：底部预留 15% 高度，避开平台 UI；字号 ≥ 28px（1080 宽），描边 2px。

**安全与版权**

- 生成图统一走内容安全审核（涉黄涉政涉暴），不通过自动重生成（≤2 次）。
- 平台素材库仅收录已授权素材；商家上传需勾选「拥有使用权」。
- 成片默认带平台/商家水印（可配置），防止二次搬运。

### 3.3 音频处理

| 子模块 | 方案 | 关键参数 |
|---|---|---|
| TTS 配音 | 云 TTS（如火山/阿里）或本地 CosyVoice；按分镜逐段合成 | 音色库 6 种（男/女 × 亲和/活力/沉稳）；语速 0.85-1.15；采样率 48kHz |
| 时长对齐 | `ffprobe` 测每段音频 → 分镜时长 = max(文案时长+0.3s, 1.5s)；整体超目标则精简文案 | 偏差 ≤50ms |
| BGM | 曲库按场景/情绪打标，按 `bgmCode` 或节奏（BPM）匹配；长度自动循环/淡出 | 音量 -24dB，人声段自动 ducking 到 -30dB |
| 音效 | 转场 whoosh、价格弹出「叮」、结尾 ding；按事件点挂载 | ≤3 个/15s，避免喧宾夺主 |
| 响度 | 两遍 loudnorm，统一到 -14 LUFS / TP -1.5dB | 平台播放一致性 |
| 混音 | FFmpeg `amix` + `sidechaincompress`（闪避），人声为主轨 | 人声 -16 LUFS 优先 |

**BGM 闪避链示例**

```
[bgm]volume=-24dB[bg]; [vo]asplit=2[vo1][vo2];
[bg][vo2]sidechaincompress=threshold=0.05:ratio=8:attack=20:release=300[bgduck];
[vo1][bgduck]amix=inputs=2:normalize=0,loudnorm=I=-14:TP=-1.5
```

### 3.4 视频渲染与合成

**分段渲染 + 拼接（核心策略）**

1. 每个分镜独立渲染为相同编码参数的 `segment_i.mp4`（H.264 / yuv420p / 30fps / 同码率），失败只重跑该镜。
2. 用 concat demuxer 无损拼接（copy），避免整片重编码。
3. 统一混音、烧字幕、faststart 封装。
4. 分镜 hash（素材 + 文案 + 参数）作为缓存键，改一个镜头只重算一个片段。

**单镜渲染命令（示意）**

```bash
ffmpeg -y -loop 1 -t 3.2 -i shot_01.jpg -i vo_01.mp3 \
  -filter_complex "\
    [0:v]scale=1080:1920:force_original_aspect_ratio=increase,\
    crop=1080:1920,zoompan=z='min(zoom+0.0006,1.08)':d=96:s=1080x1920:fps=30,\
    format=yuv420p[v];\
    [v]subtitles=shot_01.ass:fontsdir=fonts[vout]" \
  -map "[vout]" -map 1:a -c:v libx264 -preset medium -crf 20 \
  -maxrate 8M -bufsize 16M -c:a aac -b:a 192k -ar 48000 -shortest segment_01.mp4
```

**工程要点**

- 硬件加速：有 GPU 用 `h264_nvenc`（preset p4），否则 `libx264 medium`；两者输出参数保持一致，便于灰度。
- 幂等：`idem_key = hash(scriptId + resolution + watermark)`；重复提交返回同一 job。
- 续跑：`render_job_step` 记录已完成阶段与分镜清单，重试跳过已完成项。
- 超时与清理：单阶段超时（LLM 30s / TTS 60s / 单镜 120s / 整片 10min）；`tmp/` 与失败片段 7 天清理。
- 字体与多语言：字体文件随镜像分发，ASS 字幕避免系统缺字。

### 3.5 输出格式与分辨率配置

| 场景 | 分辨率 | 码率 | 帧率 | 编码 | 音频 |
|---|---|---|---|---|---|
| 竖版主输出（商家） | 1080×1920 | 8 Mbps | 30fps | H.264 High / yuv420p / faststart | AAC 192k 48kHz |
| 竖版轻量（预览/弱网） | 540×960 | 2 Mbps | 30fps | 同上 | AAC 128k |
| 方版（活动/朋友圈） | 1080×1080 | 6 Mbps | 30fps | 同上 | AAC 192k |
| 横版（公众号/教学） | 1920×1080 | 8 Mbps | 30fps | 同上 | AAC 192k |
| 封面 | 1080×1920 | — | — | JPEG q=2 | — |

- 文件命名：`{shopId}/{projectId}/v{version}/{resolution}_{timestamp}.mp4`
- 同时输出：成片、封面、字幕文件（.ass，便于二次编辑）、质检报告（JSON）
- 单文件上限 200MB；超限自动降码率重编。

## 四、交互流程

### 4.1 端到端流程（5 步向导，可在任意步骤保存草稿）

| 步骤 | 页面 | 用户动作 | 系统响应 | 耗时预期 |
|---|---|---|---|---|
| ① 选场景 | 场景卡片（菜品/门店/活动）+ 画幅 + 时长 | 点选卡片 | 预填表单与模板 | <1s |
| ② 填内容 | 卖点输入框 + 素材选择器 | 输入 1-3 条卖点，选 3-5 张图 | 实时校验（字数、图片清晰度） | 1-3min |
| ③ 改脚本 | 分镜卡片列表（图 + 文案 + 时长） | 改文案、换图、单镜重生成、调顺序 | 自动保存；改动镜标记「待重生成」 | 1-2min |
| ④ 配声音 | 音色列表 + 试听 + BGM + 音量 | 试听并选择 | 试听 3s 片段，实时合成 | 30s |
| ⑤ 渲染导出 | 进度面板 + 预览播放器 | 点「生成视频」，等待，预览/下载/发布 | 阶段进度、预估剩余、失败原因 | 60-180s |

### 4.2 关键交互设计

- **进度可见**：阶段条（脚本→素材→配音→渲染→质检）+ 百分比 + 预估剩余；SSE 推送，断线自动降级 2s 轮询。
- **先预览后正片**：渲染 540p 预览（≤45s）供确认，再出 1080p 正片，减少无效等待。
- **局部重生成**：分镜卡片右上角「换一版」，只重跑该镜素材/文案，不影响其他镜头。
- **版本对比**：保留最近 5 版脚本与成片，支持左右对比，一键回滚。
- **失败可解释**：每个失败给出原因 + 一个主行动按钮（重试 / 换素材 / 改文案）。
- **防误操作**：离开页面前若有未保存分镜修改，弹确认；渲染中离开不阻断，任务在「作品」列表继续。
- **空状态引导**：无素材时给出「上传 3 张实拍图，效果提升 60%」的明确提示与示例。

### 4.3 异常路径

| 场景 | 系统行为 | 用户看到 |
|---|---|---|
| 素材不足 | 自动用生成图/模板兜底 | 「已为第 2 镜自动生成配图，可替换」 |
| TTS 失败 | 切默认音色重试 | 「当前音色暂不可用，已切换默认音色」 |
| 渲染失败 | 断点续跑 1 次 | 「渲染中断，正在从第 3 镜继续」 |
| 质检不通过 | 自动重跑 1 次 | 「画质校验未通过，正在重新生成」 |
| 网络断开 | 任务服务端继续 | 重进页面恢复进度 |
| 超出配额 | 拦截提交 | 「今日 3 次已用完，明日 00:00 重置」 |

## 五、性能与扩展性

### 5.1 并发处理模型

- **任务分级队列**：`preview(1) > final(5) > batch(9)`；低优先级任务保证不饿死（老化：等待 >10min 提升一级）。
- **Worker 水平扩容**：按阶段独立部署，`render-worker` 按 CPU/GPU 扩；单机 4 vCPU 可跑 2 路 1080p（libx264 medium）；8 vCPU 跑 4 路；GPU（T4）NVENC 可跑 6-8 路。
- **资源隔离**：渲染进程设置 `nice` 与内存上限（2GB/任务），防止拖垮同机其他任务；素材生成走独立池，避免占用 GPU。
- **背压**：队列长度 >200 时拒绝新任务并提示预计等待；批量任务分片提交，单片 ≤20 条。
- **幂等与去重**：同一 `idem_key` 只允许一个活跃任务；重复点击「生成」不重复扣配额。

### 5.2 耗时预算（30s / 1080p / 5 镜）

| 阶段 | P50 | P95 | 优化手段 |
|---|---|---|---|
| S1 脚本 | 4s | 12s | 流式返回、模板兜底 |
| S2 素材 | 10s | 30s | 素材预索引、生成图并发、缓存 |
| S3 音频 | 8s | 20s | 分段并发 TTS、TTS 结果缓存 |
| S4 渲染 | 55s | 110s | 分段并行、NVENC、片段复用 |
| S5 质检 | 5s | 10s | ffprobe 抽检 + 并行 |
| **合计** | **82s** | **182s** | 预览版 ≤45s |

### 5.3 资源占用与成本

| 项 | 估算 |
|---|---|
| CPU 渲染 | 4 vCPU × 60s / 条 ≈ 0.07 核时 |
| 内存 | 峰值 1.2GB / 路（1080p） |
| 临时磁盘 | 输出体积 × 3（片段 + 成片 + 音频），30s 约 120MB |
| GPU（可选） | T4 每小时约 ¥2，按 6 路并发 ≈ ¥0.09/条 |
| LLM | 约 3k tokens/条 ≈ ¥0.03 |
| TTS | 400 字 ≈ ¥0.04 |
| 存储 | 成片 25MB × 180 天，按 0.12 元/GB/月 ≈ ¥0.02/条 |
| **合计** | **≈ ¥0.20-0.35/条**（不含带宽） |

### 5.4 缓存策略

| 缓存对象 | 键 | 命中收益 |
|---|---|---|
| 脚本 | hash(卖点+模板+时长) | 同店复刻省 4-12s |
| TTS | hash(文本+音色+语速) | 改画面不改文案时省 8s |
| 分镜片段 | hash(素材+文案+动效+时长) | 局部修改只重算 1 镜 |
| 素材缩略图 | assetId | 列表秒开 |
| BGM 曲库 | 本地 SSD 常驻 | 省下载 |

### 5.5 扩展性预留

| 方向 | 预留设计 |
|---|---|
| 换模型/供应商 | `ProviderRegistry` 按能力注册（LLM/TTS/IMAGE/RENDER），配置切换，无需改业务 |
| 图生视频/数字人 | 新增 `VisualProvider` 实现（图片→视频片段），流水线阶段不变 |
| 多语言 | 脚本增加 `lang` 字段，TTS/字幕/字体按语言切换 |
| 长视频 | 分章生成 → 复用分段渲染；队列按章节并行 |
| 实时预览 | 低分辨率 + 关键帧预览，WebCodecs 前端合成（P2） |
| 模板市场 | 模板即 JSON（版式/动效/字体/配色），运营后台可配置 |
| 多租户/开放 API | 项目表已带 merchant/shop，配额与鉴权可下沉到商户级 API Key |
| 数据分析 | 成片带 utm 参数，回流播放/转化数据优化模板 |

| 内容合规 | 敏感词/违规画面 0 命中 | 审核 API + 人工抽检 10% |

### 6.3 效率指标

| 指标 | 目标 |
|---|---|
| 预览版耗时（540p） | P95 ≤ 45s |
| 正片耗时（1080p/30s） | P50 ≤ 90s，P95 ≤ 180s |
| 单节点吞吐 | ≥ 8 条/小时（1080p，4 vCPU） |
| 集群吞吐 | ≥ 200 条/天（2 台 8 vCPU + 1 GPU） |
| 队列等待 | P95 ≤ 30s（非批量峰值） |

### 6.4 稳定性与可观测

- 任务成功率 ≥99%（自动重试后），失败任务 100% 有明确错误码与可执行建议。
- 服务可用性 ≥99.5%；单 Worker 崩溃不影响任务（任务回到队列，attempt+1）。
- 全链路 `traceId`：projectId → jobId → stage → 产物 objectKey 可追溯。
- 核心指标：队列长度、各阶段耗时、失败率、单条成本、GPU 利用率。
- 告警：失败率 >3%（5min）、队列积压 >50、单阶段 P95 超预算 50%。

### 6.5 安全与合规

- 鉴权：商家令牌绑定 shopId，接口层强制校验归属；管理端按角色（SUPER_ADMIN/OPERATOR/CS）控制。
- 存储：成片与素材使用签名 URL（默认 24h），禁止公开桶直读。
- 内容：生成前后双重审核；违规内容立即下架并记录。
- 版权：素材入库需授权凭证；生成图默认加 AI 生成标识（合规要求）。
- 隐私：不采集人脸特征；上传素材 180 天后可配置自动清理。
- 审计：审核、发布、删除操作全量留痕（操作人、时间、IP）。

### 6.6 验收方法

1. **自动化**：CI 跑 20 条固定用例（不同场景/时长/画幅），脚本断言 ffprobe 全部指标。
2. **人工抽检**：每版本随机抽 30 条，按 6.2 评分表盲评，均分 ≥4 方可发布。
3. **压力测试**：并发 50 任务，观察成功率、P95 耗时、队列等待、资源峰值。
4. **故障演练**：杀 Worker、断网、TTS 超时、存储不可写，验证续跑与提示。
5. **灰度**：先对 10 家商家开放，观察 7 天二次使用率与投诉率再全量。

| M4 规模化 | 2 周 | 队列分级 + 批量任务 + 监控告警 + 压测 + 灰度 |

### 7.2 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| LLM 输出不稳定 | 脚本不可用 | 强 JSON 契约 + 校验重试 + 模板兜底 |
| 生成图质量不稳定 | 成片廉价感 | 优先真实素材；生成图仅兜底；品牌 LoRA + 人工替换入口 |
| 渲染耗时超预算 | 用户流失 | 预览优先、分段并行、NVENC、片段缓存 |
| 版权/合规 | 下架与处罚 | 授权素材库 + 双重审核 + AI 标识 + 水印 |
| 成本失控 | 毛利下降 | 配额 + 缓存 + 分级画质 + 生成图限次 |
| 队列积压 | 体验下降 | 背压拒绝 + 优先级 + 弹性扩容 + 批量错峰 |
